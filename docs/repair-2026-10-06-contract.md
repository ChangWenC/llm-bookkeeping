This is the coordinator-approved repair contract on top of SPEC. Existing schema_version 1 data and accepted results remain readable and immutable. New fields and optional ports are additive; absence of a journal disposition creates publication debt rather than rejecting an old result. Owners must report any necessary signature changes before implementation.

Contracts added to src/contracts/types.ts:

- PrepareRequest.skip_units?: ReviewUnit[]; ReviewUnit = {schema_version:1,event_id,start_byte,end_byte}. event_id is the original persisted event ID; bounds are the half-open UTF-8 interval of its full original body. Extract existing context.review_slice.source_event_id/start_byte/end_byte for slices; whole bodies use [0,UTF8Bytes(body)). Skips suppress overlapping intervals for this preparation only and never write review completion. Invalid/nonexisting bounds are input errors. B preserves unsuppressed tails and applies skips before allocation, including within oversized events.
- ReviewResult.journal_dispositions?: JournalDisposition[]. Each entry is {schema_version:1,candidate_id,date,path,disposition:"patch"|"already_present"|"not_needed"|"defer",suggestion_id?,reason}. candidate_id must exist in the accepted material. patch binds an actually supplied matching page suggestion. Other dispositions require an explicit reason; already_present must be validated against the frozen baseline. Absence of entries leaves affected fact targets pending. No broad range or coverage proves journal completion.
- FileOutcome.queued_work_ids?: string[]. IDs name actual durable follow-up work. Queued historical supplement output is pending until its target is displayed; enqueue is never applied/noop file success.
- JournalPatch.supersedes_operation_id? and FileIntent.supersedes_operation_id? carry a stable automatic replacement link. Store enforces at most one automatic replacement for an original operation and terminally supersedes the original atomically; pending listings and recovery never reapply it. This does not allow overwriting a newer human edit.
- Reviewer.prepareJournalWork?(request: JournalWorkRequest): Promise<JournalWorkBundle>. request = {schema_version:1,cutoff,work_ids?,max_items?}. The returned bundle = {schema_version:1,journal_bundle_id,cutoff,work,facts,existing_facts,baselines,conflicts}. B persists its frozen selection/baselines. It contains already accepted precise fact revisions, effective related targets and current exact page baselines, without SourceEvent review chunks. Explicit max_items remains bounded by review material limits.
- Store.commitJournalResolution?(resolution: JournalResolution): Promise<JournalResolutionCommit>. resolution = {schema_version:1,resolution_id,journal_bundle_id,created_at,dispositions,pages}. disposition = {schema_version:1,work_id,disposition,suggestion_id?,reason}; pages = JournalWorkSuggestion[] ({schema_version:1,suggestion_id,work_ids,date,path,baseline_digest,mode,old_text,new_text,supersedes_operation_id?}). Return = {schema_version:1,resolution_id,reused,patches,work_ids}. Store validates selected work, current fact/target revisions, precise supplied baseline and all suggestion links; allocates stable operations and commits file intents/debt changes idempotently. It creates no facts, source review marks, ReviewResult or fact outbox. patch disposition work completes only after verified file apply/noop or verified derived display, not upon resolution acceptance.
- Store.listJournalConflicts?(): Promise<FileOutcome[]> is a real Store query over persisted patch and intent conflicts, including conflicts before a FileIntent existed. Deduplicate operation IDs. Never hard-code an empty conflict array. Status counts pending journal work, conflicting operations and unresolved/deferred journal decisions independently.
- BookkeepingConfig.daily_round_limits?: DailyRoundLimits; fields defined below. Old configs without the field retain conservative bounded preparation defaults; the coordinator's explicit personal profile enables the approved operational budgets.

## B: review windows and durable journal work

Normal daily live uses [max(config.live_start,cutoff-48h),cutoff). Normal daily history uses material older than that lower boundary; its query lane does not filter away material captured by another lane. The capture lanes remain independent physical progress. Completed daily source intervals and partial reviewed intervals deduplicate across normal live/history. Explicit replay retains its own namespace. Preserve manual range/period/replay semantics. Empty normal automatic daily preparation returns zero bundles; unknown/unread capture remains separate debt and cannot manufacture an empty semantic bundle.

On acceptance create WorkItem kind=journal_publication per exact allocated FactRef revision + affected date + canonical target path. payload is JournalPublicationPayload={schema_version:1,fact_ref,date,path,target_refs,operation_id?,disposition?}. Stable work ID derives from those exact components. Resolve all actual affected old/new target dates for replace/retract, including historical/monthly supplement targets, without resurrecting expired daily Markdown. Retain existing accepted fact refs. Unresolvable dates/targets remain local deferred work with reason. Associate initial accepted page patches to this precise debt; a successful unrelated page cannot close it. already_present/not_needed complete only their explicitly validated work; defer remains debt. Compatibility results lacking fields are accepted and queue debt for uncovered affected targets.

Journal work preparation/resolution is a file-only continuation over accepted facts and current baselines. No second source semantic review, source marks, revision allocation or outbox. Store transaction persists the resolution and replacement link; C owns actual safe byte writes. Superseded operations must disappear from pending patches, be visible as terminal history, and remain inert even when desired old bytes happen to reappear. A second automatic replacement for the same original must remain a visible local conflict/defer.

Status adds source records under sources with provider/account_id and independent capture_status, last_read_at, unread (UnknownValue<number> when not measurable), oldest_unreviewed_at (UnknownValue<string>). last_read_at reflects actual bounded read evidence, not command start or mtime. Preserve source gaps and execution failure. Add separate review/fact/page counts and journal_publication pending/conflict/unresolved counts. Never use command execution success to imply complete capture, no activity, or all pages published. Actual SQLite/storage failure is an execution failure.

Add daily_round:{schema_version:1,run_id,cutoff,started_at,capture_elapsed_ms,started_bundles,wave_started,live_started,history_started,fair_cursor,skip_units,active,receipts}. active records source,lane,bundle_id,units,result_id?; units are original event spans. After acceptance incomplete/deferred source intervals remain skipped for this run and eligible next run. ## Final integrated refinements

Journal already_present dispositions require `evidence_text` and current full frozen baseline. Still-effective not_needed requires explicit editorial reason; an old corrected/withdrawn revision additionally needs frozen retirement proof. A work carrying an original operation requires exact supersedes_operation_id on its replacement; different originals cannot share one patch. Any nonempty getOperationSupersession response, including terminal:audit_ref, makes the original inert. Journal preparation includes retirement proof revisions among existing_facts, adaptively shrinks oversized prefixes and isolates single local bad items.

Public optional Store ports include actual-acceptance inventory, explicit recovery IDs, exact revision lookup and `completeJournalDisplay(workIds,publicationOperationId,WikiWriterLock)`. The latter runs under the held monthly lock and verifies current applied output and complete exact refs before atomic debt closure/linked old-operation terminalization. Monthly derived intent refs are displayed+represented+correction union, with sorted exact refs included in the operation ID to avoid reusing an older sparse-ref noop. No new semantic state is created.

Complete daily receipts are independent immutable private files; manifest receipts contain refs and necessary bounded stage/count/status summaries. The16MiB bound is specific to the daily scheduling manifest, not a new global import/recovery gate. Same-active format repair consumes no start; `--defer-active REASON [--defer-stage review|material|publish|journal]` records actual failure and exact run skips. See [daily-round-and-journal.md](daily-round-and-journal.md) for CLI/JSON authoring, [runbook.md](runbook.md) for coordinator-only private profile draft/jq recovery selection and [daily-automation-prompt-2026-10-06.md](daily-automation-prompt-2026-10-06.md) for the formal deployment prompt.

Unread total remains unknown when only known-file offsets were measured.
