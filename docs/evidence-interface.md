# Wiki accepted-fact evidence mirror

`src/consumers/evidence/index.ts` exports `createEvidenceConsumer(store, config, options?: EvidenceOptions): Consumer`, target `evidence`. Native runtime loads it only for consume; no adapter/source initialization. `max_batches` defaults to 20 (allowed 1–100), and WriterOptions supplies synthetic clock/fault injection. CLI/config require no extra configuration.

The consumer reads only immutable ready FactArtifact through `listReadyBatches('evidence', limit + 1, after_batch_id?)`. Other consumer acknowledgements do not suppress evidence backfill. JSON output is the accepted artifact, including its facts/revisions/coverage and semantic outputs; it does not fetch/copy raw source fragments. Destination is `wiki/personal/_evidence/bookkeeping/batches/<sha256(batch_id)>.json`, readable versioned machine data without Markdown frontmatter. Each stable `evidence:<batch_id>` operation uses SafeWikiWriter/shared lock/full FileIntent. Creation baseline is absent. Existing conflicting bytes are never rebased/overwritten. Actual output bytes must equal the accepted artifact before the independent evidence acknowledgement; even an applied-intent noop is verified after later manual edits. Only actual successful writes queue index.

Local cursor `data_dir/consumers/evidence/cursor.json` is atomically saved at 0600. It is a disposable continuation optimization, not fact/ack truth: it advances past attempted batches including conflicts, wraps at the end and restarts safely when absent/malformed. Every ready read is limited; only at most max_batches artifacts are processed per run. Outstanding earlier conflicts prevent a false complete result. Concurrent runs may repeat work but stable intents, byte verification and unique acknowledgements absorb repetitions. Cursor/store/mirror failures report pending and do not block subsequent consumers in `consume all` or roll back local accepted facts/Analytics.

`kind:evidence` work tracks attempted mirror output independently. Output success completes this work before acknowledgement; a crash between these steps leaves the batch ready for safe replay. Complete work alone never suppresses replay. Mirror conflicts/failures remain explicitly unacknowledged and are discoverable through ready-batch/status ports. No new SQLite schema or source permissions are introduced.

Synthetic evidence: `tests/consumers/evidence.test.ts` uses actual SQLite and isolated Wiki roots for historical backfill after other acknowledgements, bounded reads, live lock separation, rename/registration crashes, actual-byte checks after manual edits, failed-head continuation/wrap and lost cursor. `tests/consumers/archive-acceptance-helper.test.ts` exercises the coordinator-only isolated archive helper with a controlled clock; this does not prove production/scheduled execution.
