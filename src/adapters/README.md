# Source adapters

Entry point: `createAdapters(config)` implements the public `SourceAdapter` port. Only Store's `saveCollection` may commit a yielded batch. Proved adjacent event/response mirrors are merged into the first canonical event; a persisted body hash/envelope identity continues mirror recognition across batches. Batches never contain duplicate event IDs. Native repeated message IDs are checked against a bounded per-file recent identity set. Event raw-line fragments are stable across changed read boundaries; WeChat event fragments are stable canonical source records independent of query-window batches. Adapter never advances external cursors or writes a source file. Pass both live and history checkpoints in `AdapterContext` so history can consume the prefix excluded by initial live bootstrap. Store queries use UTC event ranges; a captured source batch may contain events outside the requested range because advancing a physical byte checkpoint must never discard older/after-cutoff source events.

ISO wall clocks retain their original 1–9 fractional digits through Z/offset or explicit IANA resolution; ambiguous/nonexistent local clocks remain pending. Numeric JSON seconds in `timestamp`, `create_time` and `epoch` use a narrow lexical preservation rule for ten-digit seconds plus 1–9 decimal digits before JSON.parse. Other numeric fields keep their normal types. An already parsed Number with more than millisecond fractional precision cannot prove the original wire value and remains `numeric_time_precision_unproven`; scientific numeric notation has no exact lexical precision guarantee. No fractional digits are invented from a rounded Number. Source-proven recapture can correct saved truncated UTC metadata through Store's explicit compatibility rule; unknown/unproved conflicts stay local pending.

## File sources

Provider names `codex` and `claude`; roots are explicit directories. Reads are capped by request and the provider maximum (live 90s / 64MiB / 2000 directory entries by default; history 30s / 32MiB). First visit reads at most 64KiB header and 8MiB frozen-EOF tail in <=1MiB steps. `options.tail_bytes` may lower the tail size. Discovery stores directory offsets, pending paths and known-file rotation. Actual skipped directory entries count against the budget. Same-process Dir handles resume without rescanning. Node provides no persistent seek cookie; after restart a flat directory larger than the budget reports `minimum_directory_budget` and scanned prefix. Set explicit `options.max_directory_entries` (bounded at 65536), such as 4096 for 2077 archived entries, to allow a complete next traversal. `FileAdapter.close()` releases any cached handles at runtime shutdown. mtime only orders the bounded candidate set. Directory enumeration may revisit already skipped entries after restart; both time and actual entry budgets bound this work.

Checkpoint matching includes configured account and source-root/scope identity. Final-component symlinks are rejected with O_NOFOLLOW and canonical source paths must remain in an allowed root. Native source account/conversation/message/block identities are stable after relocation. A changed header, smaller file or changed bytes immediately before the saved offset opens another generation. Incomplete lines are captured in raw fragments and a persisted checkpoint continuation; subsequent reads resume after captured bytes and reconstruct complete JSON before parsing. Malformed lines reset mirror state and retain a gap. Continuation defaults to a bounded 64MiB per record (`options.max_line_bytes`, maximum 256MiB). A record beyond that explicit bound retains its original unparsed source range and an import-required gap; it never advances past unparsed content or claims it reviewed.

`options.allowed_project_roots` explicitly scopes cwd paths; unset means provider roots define the scope. `options.excluded_session_ids` excludes configured native identities. Subagent/automation exclusion uses source structure, never a content keyword, UUID shape, or non-cli source label. Desktop `source: vscode` and `originator: Codex Desktop` are supported. Unknown identity/time stays pending. A frozen snapshot can reach complete once source discovery, file ranges and saved history prefixes finish. Unknown future arrivals do not invalidate this completion; later captures and replay handle late data.

## WeChat

Provider `wechat`; `roots` unused. Required option: `bundle_id`; source scope uses `chats` (stable chat IDs) and/or explicit `discover_sessions: true`. Bounded sessions discovery accepts private/group plus FileHelper, excludes public/systemholder, adds `pinned_chats`, applies `ignored_chats`, and reports a limit-hit gap. `sessions_limit` defaults to 200. A durable chat rotation index prevents provider-budget failures from always blocking later chats. Optional `binary`, `limit` (default 2000, cap 10000), `ignored_chats`, `self_ids`, `self_ids_by_chat`, `identity_verified`, `verified_ranges_by_chat` or `verified_since_by_chat`, `cursor_readonly_verified`. Per-chat range maps contain UTC `{from,to}` intervals or a verified UTC start for continuing live capture; a blanket `coverage_verified` flag never proves history. Requests outside proven copy ranges retain precise missing-prefix/range gaps. Verification settings must come from the coordinator's real controlled acceptance, not doctor or synthetic tests. Account-scoped `copy_verified_since` proves continuing copy capture after that UTC instant and applies to newly discovered private chats; it never proves earlier main-WeChat history. `sender_wxid` uses verified account-scoped `self_ids`; per-chat `real_sender_id` requires a verified `self_ids_by_chat[chat]` mapping. Sender IDs must be proven within the configured account/conversation scope; never infer self from null, display name, `fromSelf`, or a magic numeric ID.

Only read-only accounts, history and opt-in sessions execute, with `--account`, `--bundle-id`, `--chat`, epoch `--since/--until`, `--order asc`, `--json`, `--no-transcribe`. For managed clones, `routing: managed_bundle` first calls read-only `accounts --json` every round and requires a unique mapping from the configured bundle to expected account wxid. It then uses only the fixed bundle flag; missing, changed, or ambiguous bindings return unavailable before querying history. No account default or alias is changed. This avoids the observed v1.18.16 rejection of a combined account+bundle route. Expected account remains the event identity. No shell, send, init, new-messages, implicit external cursor, or media fetch. Failures isolate individual chats. Live cap hits remain partial. History persists a bounded window queue, splits capped windows without treating asc as the earliest page, and captures each response atomically with the updated queue. `history_queries_per_round` defaults to 8 (maximum 16; each chat at most 4), also bounded by provider time/bytes. Single-second caps or the split depth bound become explicit import gaps and are not repeatedly queried. Completed core history is reused; new cutoffs append new core windows. After initial core enumeration drains, `history.late_sweep` independently rechecks completed windows older than live's 48 hours, starting from the newest old range and moving backwards. Each chat receives at most one ordinary late query plus at most one deferred retry per round within the unchanged total history time/byte/query budget and four-query chat cap. A persisted preference alternates core and late; a separate debt preference survives cycle changes and also rotates work when only one query slot is available. The default window is 7 days (`late_sweep_window_days`), empty uncapped windows grow fourfold up to 3650 days (`late_sweep_max_window_days`), and nonempty windows reset to the base size. Thus empty 1970–2026 scope finishes a sweep in about 11 queries, not one query per day across decades. A completed cycle waits 24 hours by default (`late_sweep_interval_ms`, bounded to 1 hour–30 days). Failures move to an independent persisted `deferred` list with timed retries; they do not prevent cycle completion or a refreshed newest snapshot. Each new cycle starts with recent work when sufficient budget exists, then uses the separate bounded retry slot for old debt; irreversible capped seconds persist as import gaps and are excluded from later cycles. Group context has its own persisted sweep windows. Dense nonempty history may need many bounded rounds: inspect `frontier`, queued window count, `blocked`, and `next_cycle_at` plus explicit pending gaps; raising finite query budgets or importing the irreducible range is the remedy. Initial unfinished core carries a late-arrival-risk gap; live never waits. Rechecking does not certify missing main-client history or erase verified-range gaps. Replay explicitly clears enumeration and sweep state. Public/systemholder sources are excluded. Group queries include up to 20 minutes preceding/following context, limited by frozen cutoff. Only in-range self participation or authoritative mentions anchor retained group context; out-of-range surrounding events have `context.context_only: true`. Such events are captured for later/context review without claiming beyond-cutoff coverage.

The public upstream probe pins wechat-use v1.18.16. Coordinator-recorded real copy identity, paging and relogin evidence is summarized in `docs/upstream-wechat.md`. Three isolated real history processes kept eleven event identities unchanged while the persisted late frontier advanced and its frozen snapshot stayed fixed; coverage remained partial. This proves bounded resumption without observed duplicates, not capture of an actual late insertion. Actual late insertion, persistent failed-window fairness, source truncation and microsecond/nanosecond boundaries remain synthetic acceptance; unavailable older main-client history remains an explicit gap. An independent eighty-day synthetic one-query/restart sequence kept the permanent failed debt at one copy while core, ordinary late and deferred work all advanced.

## Import parsers

`parseChatExport(bytes, format, manifest, config)` accepts `chatlab-json`, `chatlab-jsonl` (0.0.2 header/member/message), `legacy-json` and the confirmed `legacy-jsonl` fields. The coordinator streams/bounds large input and persists original bytes. Explicit manifest account, conversation and stable source locator are mandatory. `source_timezone` supplies an IANA zone for no-offset wall clocks (minute and second precision supported); DST ambiguous/nonexistent times remain pending. `owner_id`/`self_ids` require `identity_verified`; display names never identify Roy. Old `status: complete` is not coverage proof. Proven native IDs share account/chat source identities; otherwise physical locator/content/occurrence preserve true repeated messages and mark suspected overlap.
