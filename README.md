# LLM Bookkeeping

Open-source local bookkeeping for LLM conversations, with transactional facts, explicit review and recoverable Wiki publication.

`consume --target evidence` mirrors ready accepted facts to immutable Wiki data files independently of Analytics and local export. `consume --target all` delivers Analytics, monthly, evidence, then index. Old ready batches backfill in bounded rounds; mirror conflicts retain pending work and preserve human edits. See [docs/evidence-interface.md](docs/evidence-interface.md).

Local TypeScript bookkeeping rewrite. The full behavior specification is [SPEC.md](SPEC.md), module ports are [docs/interfaces.md](docs/interfaces.md), and operating steps are [docs/runbook.md](docs/runbook.md).

Use exactly Node 25.8.0. There are no runtime npm dependencies; the checked-in lock is generated by npm. Node runs native TypeScript and `node:sqlite`. `npm test` runs synthetic verification. `node src/cli.ts --help` prints the command inventory. CLI stdout is JSON; stderr contains diagnostics. Exit 0 includes ordinary partial/pending, 1 is execution unavailable/failure, 2 is invalid input.

The CLI connects native collection, actual SQLite semantic state, independent export and Wiki publication, monthly/archive/index consumers and manifest import/migration with exact Analytics history mapping. Typed Analytics consumer, weekly/monthly semantic acceptance, Analytics review, explicit project/log page preparation and health validation call their concrete services. Exact observation/capability review effects, candidate definition promotion, as-of contract expiry and professional four-week pilot are exercised through actual SQLite/CLI integration. Implemented routes and synthetic tests do not imply complete production SPEC acceptance. Synthetic verification is not production acceptance. Actual source coverage, WeChat identity/paging, manual production daily, two scheduled dailies and retirement must be separately evidenced per SPEC.
